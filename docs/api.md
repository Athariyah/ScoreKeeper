# ScoreKeeperApp — API Contract (Volleyball & Tennis)

Локальное приложение. Базовый URL: `http://localhost:8000`. WebSocket: `ws://localhost:8000`.

## Общий формат состояния матча

Структура JSON **зависит от вида спорта (`sport`)**, но общие поля (`status`, `players`, `server`, `winner`) всегда одинаковы.

**Волейбол (`sport: "volleyball"`):**

```json
{
  "sport": "volleyball",
  "status": "IN_PROGRESS",
  "players": ["Иванов", "Петров"],
  "sets": [24, 20],
  "sets_won": [1, 0],
  "current_set": 3,
  "server": 0,
  "winner": null,
  "timeouts_used": [1, 0],
  "timeouts_per_set": 2,
  "timer": null
}
```

- `sets` — очки в текущей партии.
- `sets_won` — выигранные партии.
- `current_set` — номер текущей партии.
- `revision` — номер версии состояния; растёт при каждом изменении и не сбрасывается при новом матче. Клиент игнорирует ответ, у которого `revision` меньше уже полученного (при быстрых нажатиях ответы HTTP приходят не по порядку). Есть во всех ответах со счётом, в WebSocket-сообщениях и в `GET /api/match/state`.
- `timeouts_used` — сколько тайм-аутов каждая команда уже взяла **в текущей партии** (в новой партии счётчик обнуляется).
- `timeouts_per_set` — лимит тайм-аутов на команду в партии (2).
- `timer` — идущий тайм-аут или `null` (см. ниже).

**Теннис (`sport: "tennis"`):**

```json
{
  "sport": "tennis",
  "status": "IN_PROGRESS",
  "players": ["Джокович", "Надаль"],
  "points": [4, 3],
  "points_display": ["AD", "40"],
  "games": [2, 3],
  "sets_won": [0, 1],
  "set_scores": [[3, 6]],
  "current_set": 2,
  "tiebreak": false,
  "auto_serve": true,
  "server": 1,
  "winner": null,
  "timer": null
}
```

- `points` — сырые очки для логики (числа).
- `points_display` — **текст для вывода на экран** (0, 15, 30, 40, AD). Именно этот массив необходимо использовать для отображения счёта.
- `games` — выигранные геймы в текущем сете.
- `sets_won` — выигранные сеты.
- `set_scores` — счёт завершённых сетов по порядку, всегда в порядке «игрок 1 : игрок 2» (`[[6, 3], [4, 6]]`). Сет, выигранный в тай-брейке, записывается как `[7, 6]`.
- `current_set` — номер текущего сета (`sets_won` обоих игроков + 1).
- `tiebreak` — `true`, пока в сете 6:6 и играется тай-брейк (до 7 очков с разницей минимум в 2; `points_display` в нём — обычные числа `"3"`, `"5"`).
- `auto_serve` — автосмена подачи (`true` по умолчанию): подающий меняется после каждого гейма, а в тай-брейке — по правилам (первое очко, затем по два). При `false` подачу ведёт оператор.
- `timer` — перерыв на смену сторон или `null` (см. ниже).

Счёт в гейме показывается в формате `0 / 15 / 30 / 40 / AD`: при `40:0`, `40:15` и `40:30` в `points_display` приходит `["40", "0"]` и т. д., `AD` — только после равных `40:40`.

**Объект `timer`** (одинаков для обоих видов спорта; `null`, если таймер не идёт или истёк):

```json
{ "kind": "timeout", "team": 0, "duration": 30, "remaining": 21.4 }
```

- `kind` — `timeout` (тайм-аут команды, волейбол, 30 с) или `changeover` (смена сторон, теннис, 90 с).
- `team` — индекс команды, взявшей тайм-аут (`null` для `changeover`).
- `duration` — полная длительность в секундах, `remaining` — сколько осталось на момент отправки.
- Клиенты считают отсчёт сами от момента получения сообщения; новое сообщение со счётом пересинхронизирует таймер.
- Таймер останавливается сам, как только начислено очко, выполнен откат, правка счёта, сброс или завершение матча.

## 1. Начать матч

**`POST /api/match/start`**

**Тело запроса:**

```json
{
  "sport": "volleyball",
  "player1": "Иванов",
  "player2": "Петров",
  "server_index": 0,
  "config": {
    "sets_to_win": 2,
    "set_points": [25, 25, 25, 25, 15]
  }
}
```

**Поле `config` (необязательное, используется только для волейбола):**

Позволяет настроить правила матча с экрана «Настрой свой матч».

- `sets_to_win` — сколько партий нужно выиграть для победы (2 для игры до 3-х партий, 3 для игры до 5-ти партий).
- `set_points` — массив из 5 чисел. Указывает, до скольких очков играется каждая партия (1-я, 2-я, 3-я, 4-я и тай-брейк).

Примеры:
- Короткая игра: `[15, 15, 15, 15, 15]`.
- Длинная игра: `[25, 25, 25, 25, 15]`.

Если `config` не передан, используются настройки по умолчанию: 2 победы, партии до 25 очков, тай-брейк до 15 очков.

**Ответ 200:** объект состояния матча.

**Ошибки:**
- `400` — неизвестный вид спорта, неверный `server_index` или некорректный `config`.

> Ответ с ошибкой всегда содержит `{"detail": "..."}`. Если на запрос приходит `404` с `detail: "Not Found"`, то запущена **устаревшая версия бэкенда** без этого маршрута (например, без `/timeout`) — её нужно перезапустить/пересобрать.

---

## 2. Получить текущее состояние

**`GET /api/match/state`**

**Ответ 200:** объект состояния матча.

**Ошибки:**
- `404` — матч не запущен.

---

## 3. Начислить очко

**`POST /api/match/point`**

**Тело запроса:**

```json
{
  "player_index": 0
}
```

**Ответ 200:** обновлённое состояние матча.

**Ошибки:**
- `400` — неверный `player_index` (допустимые значения: 0 и 1).
- `404` — нет активного матча.
- `409` — матч уже завершён или ещё не начат.

---

## 4. Убрать последнее очко (кнопка «Откат»)

**`POST /api/match/remove-point`**

Без тела запроса. Откат возвращает состояние **целиком**: если очко закрыло гейм, сет или партию, они тоже «открываются» заново, а счётчик тайм-аутов возвращается к значению той партии.

**Ответ 200:** обновлённое состояние матча.

**Ошибки:**
- `404` — нет активного матча.
- `409` — матч уже завершён.

---

## 5. Полная правка счёта (кнопка «Корректировка»)

**`POST /api/match/set-score`**

Принимает JSON, **полностью соответствующий формату выбранного вида спорта** (см. раздел «Общий формат состояния матча» в начале документа).

Важно:
- Для тенниса обязательно передавать все поля, включая `points`, `points_display` и `games`.
- Для тенниса обязательны `points` (очки текущего гейма, сырые: 0, 1, 2, 3…), `games`, `sets_won`, `server` и `status`; необязательны `auto_serve` (`true` / `false`) и `set_scores`. Если `set_scores` не передан, история сетов сохраняется, но обрезается до числа выигранных сетов.
- Для волейбола обязательно передавать `sets`, `sets_won`, `current_set`, `server` и `status`. Необязательное поле `timeouts` (`[2, 1]`) задаёт использованные тайм-ауты в текущей партии; если его нет, они не меняются.

**Ответ 200:** обновлённое состояние матча.

**Ошибки:**
- `400` — не хватает полей или значения некорректны.
- `404` — нет активного матча.

---

## 5а. Тайм-аут команды (волейбол)

**`POST /api/match/timeout`**

```json
{ "player_index": 0 }
```

Каждая команда может взять **2 тайм-аута по 30 секунд в каждой партии**. Бэкенд запускает таймер (`timer.kind = "timeout"`, `duration = 30`), увеличивает `timeouts_used` и рассылает счёт по WebSocket. Пока идёт тайм-аут, второй запустить нельзя.

**Ответ 200:** обновлённое состояние матча.

**Ошибки:**
- `400` — неверный `player_index` или вид спорта без тайм-аутов (теннис).
- `404` — нет активного матча.
- `409` — матч не идёт, лимит тайм-аутов команды в этой партии исчерпан или другой таймер уже запущен.

---

## 5б. Остановить таймер

**`POST /api/match/timer/cancel`**

```json
{ "refund": false }
```

Тело необязательно. Останавливает идущий тайм-аут (волейбол) или перерыв на смену сторон (теннис). С `"refund": true` тайм-аут возвращается команде — на случай ошибочного нажатия.

**Ответ 200:** обновлённое состояние матча.

---

## 6. Сбросить матч (кнопка «Сброс»)

**`POST /api/match/reset`**

Без тела запроса.

Сбрасывает счёт, но оставляет имена игроков.

**Ответ 200:** состояние матча со сброшенным счётом.

---

## 7. Принудительно завершить матч (кнопка «Завершить матч»)

**`POST /api/match/force-end`**

Без тела запроса.

**Ответ 200:** обновлённое состояние матча (статус меняется на `FINISHED`, победитель — `null`).

**Ошибки:**
- `404` — нет активного матча.
- `409` — матч уже завершён.

---

## 8. Вывести текст на экран (кнопка «Вывести текст»)

**`POST /api/match/text`**

**Тело запроса:**

```json
{
  "text": "Разминка 5 минут"
}
```

**Ответ 200:**

```json
{
  "message": "Text broadcasted"
}
```

## 9. WebSocket — живая трансляция

**`WS /ws/match`**

Экран наблюдателя (и превью) подключается к этому адресу один раз.

Сервер самостоятельно отправляет JSON-объекты при каждом изменении. У каждого сообщения есть два поля:

- `type` — тип сообщения.
- `data` — данные сообщения.

**Вариант А: Обновление счёта**

```json
{
  "type": "score",
  "data": {
    "...": "объект состояния матча"
  }
}
```

Фронтенд: если пришёл `type: "score"`, берём `data` и перерисовываем табло.

**Вариант Б: Вывод текста на экран**

```json
{
  "type": "text",
  "data": "Разминка 5 минут"
}
```
