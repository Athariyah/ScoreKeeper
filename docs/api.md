# ScoreKeeperApp — API Contract (Volleyball & Tennis)

Локальное приложение. Базовый URL: `http://localhost:8000`. WebSocket: `ws://localhost:8000`.

## Общий формат состояния матча

Структура JSON **зависит от вида спорта (`sport`)**, но общие поля (`status`, `players`, `server`, `winner`) всегда одинаковы.

**Волейбол (`sport: "volleyball"`):**

```json
{
  "sport": "volleyball",
  "status": "IN_PROGRESS",
  "players": ["Иванов", "Петров"],
  "sets": [24, 20],
  "sets_won": [1, 0],
  "current_set": 3,
  "server": 0,
  "winner": null
}
```

- `sets` — очки в текущей партии.
- `sets_won` — выигранные партии.
- `current_set` — номер текущей партии.

**Теннис (`sport: "tennis"`):**

```json
{
  "sport": "tennis",
  "status": "IN_PROGRESS",
  "players": ["Джокович", "Надаль"],
  "points": [4, 3],
  "points_display": ["AD", "40"],
  "games": [2, 3],
  "sets_won": [0, 1],
  "server": 1,
  "winner": null
}
```

- `points` — сырые очки для логики (числа).
- `points_display` — **текст для вывода на экран** (0, 15, 30, 40, AD). Именно этот массив необходимо использовать для отображения счёта.
- `games` — выигранные геймы в текущем сете.
- `sets_won` — выигранные сеты.

## 1. Начать матч

**`POST /api/match/start`**

**Тело запроса:**

```json
{
  "sport": "volleyball",
  "player1": "Иванов",
  "player2": "Петров",
  "server_index": 0,
  "config": {
    "sets_to_win": 2,
    "set_points": [25, 25, 25, 25, 15]
  }
}
```

**Поле `config` (необязательное, используется только для волейбола):**

Позволяет настроить правила матча с экрана «Настрой свой матч».

- `sets_to_win` — сколько партий нужно выиграть для победы (2 для игры до 3-х партий, 3 для игры до 5-ти партий).
- `set_points` — массив из 5 чисел. Указывает, до скольких очков играется каждая партия (1-я, 2-я, 3-я, 4-я и тай-брейк).

Примеры:
- Короткая игра: `[15, 15, 15, 15, 15]`.
- Длинная игра: `[25, 25, 25, 25, 15]`.

Если `config` не передан, используются настройки по умолчанию: 2 победы, партии до 25 очков, тай-брейк до 15 очков.

**Ответ 200:** объект состояния матча.

**Ошибки:**
- `400` — неизвестный вид спорта.

---

## 2. Получить текущее состояние

**`GET /api/match/state`**

**Ответ 200:** объект состояния матча.

**Ошибки:**
- `404` — матч не запущен.

---

## 3. Начислить очко

**`POST /api/match/point`**

**Тело запроса:**

```json
{
  "player_index": 0
}
```

**Ответ 200:** обновлённое состояние матча.

**Ошибки:**
- `400` — неверный `player_index` (допустимые значения: 0 и 1).
- `404` — нет активного матча.
- `409` — матч уже завершён.

---

## 4. Убрать последнее очко (кнопка «Откат»)

**`POST /api/match/remove-point`**

Без тела запроса.

**Ответ 200:** обновлённое состояние матча.

**Ошибки:**
- `404` — нет активного матча.
- `409` — матч уже завершён.

---

## 5. Полная правка счёта (кнопка «Корректировка»)

**`POST /api/match/set-score`**

Принимает JSON, **полностью соответствующий формату выбранного вида спорта** (см. раздел «Общий формат состояния матча» в начале документа).

Важно:
- Для тенниса обязательно передавать все поля, включая `points`, `points_display` и `games`.
- Для волейбола обязательно передавать `sets` и `current_set`.

**Ответ 200:** обновлённое состояние матча.

---

## 6. Сбросить матч (кнопка «Сброс»)

**`POST /api/match/reset`**

Без тела запроса.

Сбрасывает счёт, но оставляет имена игроков.

**Ответ 200:** состояние матча со сброшенным счётом.

---

## 7. Принудительно завершить матч (кнопка «Завершить матч»)

**`POST /api/match/force-end`**

Без тела запроса.

**Ответ 200:** обновлённое состояние матча (статус меняется на `FINISHED`, победитель — `null`).

**Ошибки:**
- `404` — нет активного матча.
- `409` — матч уже завершён.

---

## 8. Вывести текст на экран (кнопка «Вывести текст»)

**`POST /api/match/text`**

**Тело запроса:**

```json
{
  "text": "Разминка 5 минут"
}
```

**Ответ 200:**

```json
{
  "message": "Text broadcasted"
}
```

---

## 9. WebSocket — живая трансляция

**`WS /ws/match`**

Экран наблюдателя (и превью) подключается к этому адресу один раз.

Сервер самостоятельно отправляет JSON-объекты при каждом изменении. У каждого сообщения есть два поля:

- `type` — тип сообщения.
- `data` — данные сообщения.

**Вариант А: Обновление счёта**

```json
{
  "type": "score",
  "data": {
    "...": "объект состояния матча"
  }
}
```

Фронтенд: если пришёл `type: "score"`, берём `data` и перерисовываем табло.

**Вариант Б: Вывод текста на экран**

```json
{
  "type": "text",
  "data": "Разминка 5 минут"
}
```
